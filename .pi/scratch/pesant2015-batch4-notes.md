## idx 19 — Simple and Scalable Time-Table Filtering for the Cumulative Constraint (lines 5532–5774, full)
- **Problem:** Cumulative is essential in scheduling/packing, and time-tabling is its lightest filtering. The best known theoretical bound is O(n log n) (Ouellet & Quimper), the synchronized sweep of Letort et al. at O(n²) is "considered as the most scalable approach" but "is not trivial to implement"; this paper gives a simple O(n²) two-step alternative (build the mandatory profile, then update all task bounds) plus an O(n) algorithm via range-max queries, reporting it outperforms synchronized sweep and the time-table implementations of open-source solvers on large-scale instances, "sometimes significantly" (L5538, abstract).
- **Model/formulation:** single cumulative resource with discrete finite capacity C ∈ ℕ and n tasks Ω = {1,…,n}; task i has start s_i ∈ ℤ, fixed duration d_i ∈ ℕ, end e_i ∈ ℤ with s_i + d_i = e_i, consumes c_i ∈ ℕ, non-preemptive (L5544). Cumulative: ∀t ∈ ℤ: Σ_{i∈Ω: s_i ≤ t < e_i} c_i ≤ C (L5544). Definition 1 — mandatory part = interval [s̄_i, e̲_i[, present only when latest start < earliest end (L5562). Definition 2 — time-table TT_Ω = aggregation of all mandatory parts, step function Eq. (1) `TT_Ω = t ∈ ℤ → Σ_{i∈Ω | s̄_i ≤ t < e̲_i} c_i` (L5572–5574); overloaded iff ∃t: TT_Ω(t) > C (L5576); TT computable in O(n) by sweep when tasks are sorted by latest start and earliest end, refs [2, 11, 15] (L5580).
- **Model/formulation (cont.):** Eq. (2) `(t < C) ⇒ t < s_i` gives the start-time rule, end times updated symmetrically (L5582–5586). Rectangle ⟨a_j, b_j, h_j⟩ with start a_j, end b_j, height h_j, length b_j − a_j; TT_Ω is a contiguous sequence Eq. (3) `⟨−∞, a_1, 0⟩, ⟨a_1, b_1, h_1⟩, …, ⟨a_m, b_m, h_m⟩, ⟨b_m, ∞, 0⟩` with b_i = a_{i+1}, Eq. (4) (L5586–5592); sequence is minimal (no consecutive rectangles share height), so rectangles ≤ 2n + 1 (L5600). Definition 3 — left-conflicting rectangle in TT_{Ω\i}: `(a_j < e̲) ∧ (b_j ≥ s̲_i) ∧ (h_j > C − c_i)` (L5604); Eq. (5) `j in left-conflict ⇒ b_j ≤ s_i` (L5606); Definition 4 — left/right time-table consistency, no task has a conflicting rectangle (L5612).
- **Existing algorithms (as stated):** sweep-line of Beldiceanu et al. [2] builds the mandatory profile on-the-fly, heap-organizes tasks, pushes tasks right until no left-conflict, O(n²) (L5618). Idempotent sweep-line of Letort et al. [11] uses dynamically appearing mandatory parts, reaches left-time-table consistency in O(n²), O(n² log n) in its faster practical implementation (L5620). Interval-tree algorithm of Ouellet & Quimper [14]: profile built first, rectangles inserted by decreasing height, tasks by increasing height, log n tree check; filtering weaker because it pushes i only after rectangles overlapping [s̲_i, e̲_i[, complexity O(n log n) (L5622).

Page footnotes printed as text at L5548, L5550, L5552 ("G. Pesant (Ed.): CP 2015, LNCS 9255, pp. 149–157, 2015.", "DOI: 10.1007/978-3-319-23219-5 11") — observations only. Verbatim captions: "Fig. 1. Task i has a mandatory part [s̄_i, e̲_i[ if its latest start time s̄_i is smaller than its earliest end time e̲_i" (L5568); "Fig. 4. - **Exact results (cont.):** Proposition 1 (L5646): j* = argmax{h_j | ⟨a_j,b_j,h_j⟩ ∈ TT_Ω ∧ [a_j,b_j[ ∩ [s̲_i, min(e̲_i, s̄_i)[ ≠ ∅}; j* is in left-conflict iff `h_{j*} + c_i > C`, otherwise i has no left-conflicting rectangle (proof L5648). Index queries j_1(i) = rectangle containing s̲_i, j_2(i) = rectangle containing min(e̲_i, s̄_i) − 1 (L5658–5660).
- **Exact results (cont.):** Algorithm 1. MinLeftTTLinearTime(Ω, C) (L5665–5677): build TT_Ω; `if max_{j∈[1;m]} h_j > C then return true`; heights ← [h_1…h_m]; rmq(heights) init at line 5 (L5672); for i with s̲_i < s̄_i: j* ← rmq(heights, j_1(i), j_2(i)); if `h_{j*} + c_i > C` then s̲_i ← b_j (L5673–5725). Whole algorithm is O(n): w-bit integer time points sorted in linear time, profile linear, RMQ preprocessing linear, queries constant time [7] (L5679). The task is pushed after the highest conflicting rectangle, "which is not as good as the filtering of [14]" (L5662), and pruning is weaker than [14] because the largest height is chosen instead of the largest end (L5638).
- **Exact results (cont.):** Algorithm 2. ScalableTimeTable(Ω, C) (L5700–5727), two phases (L5687): Ω_u = {i | s̲_i < s̄_i}; profile built only from tasks that have a mandatory part (L5689); profile indices j_1(i) (contains s̲_i) and j_2(i) (contains ē_i − 1) stored in a residue between calls, recompute by dichotomic search O(log n) only for tasks with an invalid residue, vs the O(n log n) task sorting of [2] (L5691, footnote 2 "this is similar to residual supports for AC algorithms [10]", L5697); per-task linear left/right sweeping, no height-factorized global sweeping, main part worst-case O(n²) (L5693); fruitless fixed-task removal at profile extremities, O(n): `Ω ← Ω \ {i | ē_i ≤ s_min^u ∨ e_max^u ≤ s̲_i}`; Ω kept in the search tree with a reversible sparse-set [5] (L5695).
- **Exact results (cont.):** Experiments: ScalableTimeTable tested against time-table filtering of or-tools [12], Choco3 [4], Gecode [9]; Choco3 and Gecode use the algorithm of [2]; or-tools also builds the time-table structure before filtering; no public implementation of Letort et al. [11] is available, so the heap-based variant (faster in practice) was implemented in OscaR [13] as the competitor; cumulative propagators enforce only the resource constraint, precedences by separate propagators (L5731). Generated instances: n ranging 100–12800, duration 200–2000, heights 1–40, capacity fixed to 100; greedy heuristic selects the task with the smallest earliest possible start, so no backtrack, and every solver behaves identically (L5733). Choco3 and Gecode time-tables "are quickly not able to scale well for more than 1600 tasks"; or-tools, Letort et al. and the new algorithm "are still able to handle 12800 tasks", and the new algorithm outperforms Letort et al. "despite its simplicity" (L5733). Results are given only as a chart image, Fig. 5 (L5735) — no numeric runtime table is printed in the extracted text.
- **Conclusions/claims:** the O(n) filtering is "more of theoretical rather than practical interest" — RMQ initialization "hides non-negligible constants", the procedure may be called several times before reaching the fix-point, and it does not suffer the slow-convergence phenomenon of [3] (L5683); pushing a task further right as in [2] may be more efficient than one update per task per call (L5683). RMQ is judged useful for later scheduling work, "for instance in time-table disjunctive reasoning [8]" (L5741). The simple O(n²) filtering "outperforms current implementations of timetable constraints in some open-source solvers and also the recent synchronized sweep algorithm" (L5741). Resources released at http://bit.ly/cumulativett (L5741).

## idx 20 — General Bounding Mechanism for Constraint Programs (lines 5775–6046, full)
- **Problem:** CP has no easy way to automatically derive a good objective bound, unlike IP solvers built on linear relaxation; Lagrangian relaxation (LR) coupled with CP loses the original structure and needs linear penalized constraints, so nonlinear global constraints (all-different, global cardinality, regular) cannot be dualized. This paper builds a general Lagrangian-decomposition (LD) bounding scheme for any CP, instantiated on knapsack and regular constraints, and compares it to pure CP on the multidimensional knapsack problem (MKP) and a simple shift scheduling problem (SSP) (L5781, L5805, L5809).
- **Model + formulation:** LD (Guignard & Kim [10], "variable splitting") creates copies of the variables connecting substructures, one copy per substructure, and dualizes the equality of a variable and its copy; LD bounds are "always at least as tight as those from LR" (L5807). Relaxation: max{z = cᵀx | C₁(x) ∧ C₂(x)} = max{cᵀx + uᵀ(x−y) | C₁(x) ∧ C₂(y) ∧ x=y} ≤ max{cᵀx + uᵀ(x−y) | C₁(x) ∧ C₂(y)} = max{(cᵀ+uᵀ)x | C₁(x)} + max{−uᵀy | C₂(y)} with multipliers u ≥ 0; generalized to m constraints with copies xⁱ, xⁱ = x¹ for i = 2…m, giving max{(cᵀ + Σ_{i=2..m} u(i)ᵀ)x¹ | C₁(x¹)} + Σ_{i=2..m} max{−u(i)ᵀxⁱ | C_i(xⁱ)} (L5853, L5858, L5881). Non-numeric CP domains (the characters of a regular constraint) are handled by applying LD not to X_i but to binary x_{i,v} ∈ {0,1}, x_{i,v} = 1 ⟺ X_i = v, one multiplier per binary variable (L5883).
- **Model + formulation (cont.):** Knapsack constraint `wx ≤ W` — W scalar, x = [x₁…xₙ] binary, w = [w₁…wₙ] coefficients (L5815). MKP: Eq. (1) Maximize Σ_{i=1..n} p_i x_i, Eq. (2) Σ_{i=1..n} w_ij x_i ≤ C_j for j = 1…m, Eq. (3) x_i ∈ {0,1} (L5826, L5830, L5834). Regular constraint = finite automaton π = (Q, A, τ, q₀, F): Q states, A alphabet, τ transition table, q₀ initial, F final (L5837–5841); REGULAR([X₁…Xₙ], π) holds iff the value sequence is in the regular language of a deterministic FA, verified by q_{i₀} = q₀, (q_{i_k}, X_i, q_{i_{k+1}}) ∈ τ, q_{i_n} ∈ F (L5843). Pesant [16] filtering = layered graph whose rows are automaton states, extended to Soft-regular [23], Cost-regular [6], Multicost-regular [14] that bound global cost, solved by shortest/longest paths in an acyclic graph (L5845). SSP model: Eq. (4) Maximize Σ_{j∈T} C_j, Eq. (5) REGULAR(X, π_i) ∀π_i ∈ Π, Eq. (6) ELEMENT(X_j, p_ij, C_j) ∀i ∈ W, j ∈ T, Eq. (7) X_j ∈ W, Eq. (8) C_j ∈ ℝ with min_i p_ij ≤ C_j ≤ max_i p_ij — C_j = p_ij iff X_j = i, the profit of each assignment (L5856–5873).
- **Bound computation:** subgradient method (Shor et al. [21]) solves the Lagrangian dual: u^{k+1} = u^k + t_k(y^k − x^k) Eq. (9), t_k = λ(Z^{k−1} − Z*)/‖y^{k−1} − x^{k−1}‖², 0 ≤ λ ≤ 2 Eq. (10), Z* = estimated optimum, λ controls convergence (L5885–5891). Knapsack subproblems = 0/1 knapsacks, DP in pseudo-polynomial time O(nW), adapted from Trick [22]'s filtering graph (L5913): n+1 layers, node (j,k) = layer + accumulated weight, L₀ = {(0,0)}, edge labelled 1 from (j−1,k−w_j) to (j,k) and 0 from (j−1,k) to (j,k); Trick removes nodes/edges not on a path (0,0) → (n,k) for 0 ≤ k ≤ C, and drops 1 (resp. 0) from dom(x_j) when no labelled edge remains between layers j−1, j (L5913, L5915). Edge costs c_j + Σ_{l=2..m} u(l,j) for i = 1, −u(i,j) for i ≥ 2; longest-path DP M[j,k] = 0 if k = j = 0, −∞ if k > j = 0, max(M[j−1,k], M[j−1,k−w_j] + addedCost); optimal bound = max_{0≤j≤W} M[n,j], the greatest cost over valid assignments (L5917–5923).
- **Bound computation (cont.):** regular constraint graph: multiplier u(i,j,a) for binary x_ja (X_j = a ∈ A), edge (q₁, a, q₂) costs p_aj + Σ_{l=2..m} u(l,j,a) for constraint i = 1 and −u(i,j,a) for i > 1; R[j,q] = 0 if j = 0, else max_{((j−1,q₁),(j,q),a) ∈ E} (R[j−1,q₁] + addedCost); every layer-0-to-layer-n path is a valid assignment, so the bound is max_{q∈F} R[n,q] (L5929–5937). Subgradient settings: Z* = best incumbent, λ = 2, halve λ after five iterations without improvement, iterations per node fixed to 60 for MKP (DP subproblems) and 10 for all other cases, stop as soon as the Lagrangian bound is inferior to the incumbent (L5941). Initial multipliers u₀ = 1 at the root, inherited from the parent at other nodes; testing "best bound" vs "last multipliers of the parent" shows the latter is generally better, because few iterations per node give loose bounds and more iterations at early nodes yield better multipliers later (L5943).
