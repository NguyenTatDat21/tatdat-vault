## idx 56 — Scheduling Running Modes of Satellite Instruments Using Constraint-Based Local Search (Victory Barles (B), Edouard Leurent, Philippe Geniaud, J. B. Dokan? — ONERA/Toulouse? author block unclear; source lines 17746-18059; pp. 704-719, DOI 10.1007/978-3-319-23219-5 48)

- Problem: after the acquisition plan is decided, the ground mission center must give the satellite low-level plans defining, for each instrument, successive transitions between running modes O (Off), S (Standby), H (Heat), A (Acquisition). The mode automaton (Fig. 1a) allows OS, SO, SH, HS, HA, AH and configuration-loading transitions SS/HH (chgConf); an acquisition a over [t1,t2] requires every instrument used by a to be in mode A over that interval; transitions generate sequences of on-board basic commands. Mode-transition scheduling must be solved in a few seconds, several times a day, and is the last step of the mission programming process.
- Three constraint families: (1) duration constraints — minimum time in each mode plus fixed duration for each transition; (2) non-overlap — transitions on instruments I1 and I2 cannot overlap except when they are the same transition (both are managed by the same on-board monitor which can send only one common command sequence at a time); an off↔standby transition on I3 cannot run in parallel with an off↔standby transition on I1 or I2; no transition during acquisitions (disturbance risk); (3) resource — thermal consumption per instrument per orbit ≤ ThMax_i. Objectives: minimize the number of times instruments are switched off (long-term reliability), then minimize total thermal consumption (antagonistic criteria — adding off periods reduces thermal consumption).
- Formal model (eqs. 1-17): data = orbits O with TsOrb_o/TeOrb_o and horizon [Ts,Te]; instruments I with DuMin_{i,m}, Du_{i,t}, ThRate_{i,s}, ThMax_i; acquisitions A with fixed TsAcq_a and DuAcq_a and Conf_{a,i} (nil if unused); incompatibility 4-tuples Inc = (i,i′,t,t′), e.g. (I1,I2,SH,OS) ∈ Inc. Nacqs_i = number of acquisitions using instrument i, Acq_{i,u} = acquisition of the u-th use. Allowed state sequences per global transition type (Fig. 2): 2 decompositions for the initial transition, 4 for same-configuration gaps, 6 for distinct-configuration gaps, 1 for the final transition; state sequences like [A,AH,H,HS,S,SH,H,HS,S,SH,H,HA,A] (warm up and cool down between two acquisitions) are excluded.
- Decision variables: state interval itv = presence variable pres(itv), integer start(itv), integer end(itv), fixed state S(itv) ∈ S, fixed instrument I(itv); global transition intervals gitv with start/end and type {TransInit, TransSameConf, TransChangeConf, TransEnd}; itvAcq_a, mandatory itvHA_{i,u} and itvAH_{i,u}, itvTrans_{i,u} for u ∈ [1..Nacqs_i+1]; sequence Seq_i = [itvTrans_{i,1}, itvHA_{i,1}, itvAcq_{a1}, itvAH_{i,1}, …, itvTrans_{i,n+1}]; decomposition choice variable decomp_{i,u} ∈ [1..Ndec_{i,u}] and optional state intervals Dec_{i,u,d}; Min(itv)/Max(itv) bounds; ItvOrb_{i,o} = intervals overlapping orbit o for instrument i. Constraints 1-15: presence of all Seq_i intervals; start(first(Seq_i)) = Ts and end(last(Seq_i)) = Te; contiguity within Seq_i and Dec_{i,u,d}; presence ⇔ decomp_{i,u} = d; mode intervals ≥ DuMin, transition intervals = Du; acquisition start/duration fixed; no transition during acquisitions; incompatible transitions must not overlap; per-orbit thermal sum ≤ ThMax_i with d(itv) = overlap duration. Objectives: eq. 16 card{itv : S(itv)=O ∧ pres(itv)=1}, eq. 17 thermal sum.
- Problem analysis: constraint-based scheduling with temporal + resource constraints and optional tasks; related to Job Shop Scheduling (one job per instrument, optional operations = its state intervals) but shared operations (acquisition tasks need several instruments simultaneously), contiguity requirements, and hierarchical decompositions (HTN-like; alternative constraint [Laborie & Rogerie FLAIRS 2008 555-560]; regular constraint [Pesant CP 2004 482-495]); non-standard criteria (not makespan/tardiness), some transitions should be as early as possible and some as late as possible for resource reasons.
- CBLS encoding (InCELL engine, Pralet & Verfaillie ICAPS 2013): complete assignments, invariants x ← exp maintained incrementally; Simple Temporal Network invariant [time-dependent STN, RAIRO OR 2013] gives est(itv), lst(itv), eet(itv), let(itv); explicit topological ordering topoOrder for intervals that must not overlap (eqs. 18-19 reformulate noOverlap); mandatory precedence graph avoids precedence cycles (moves that put itv after itv′ move mandatory successors too); itvHA and itvAcq merged in the order (and itvAH with itvAcq) because transitions cannot overlap acquisitions.
- Thermal lower bound: in each decomposition one interval can be identified as the lowest-consumption interval to enlarge (underlined labels in Fig. 2); rewriting eq. 15 with est/let for the interval to enlarge, est/eet for intervals on its left and lst/let on its right gives a thermal lower bound (valid under the assumption that the SS (resp. HH) consumption equals the S (resp. H) consumption — footnote).
- Soft constraints: due dates (constraints 3 and 11) and the thermal constraint (15) are soft, the rest hard; constraint 11 split into eq. 20 (start(itvAcq_a) ≥ TsAcq_a), eq. 21 (lock_a = 1 → start ≤ TsAcq_a) and eq. 22 delay_a ← est(itvAcq_a) − TsAcq_a; lock_{|A|+1} with delay_{|A|+1} ← max_{i∈I} (eet(last(Seq_i)) − Te); violation degree thv_{i,o} ← max(0, thermal sum − ThMax_i) (eq. 23). When all locks are 0 and there is no precedence cycle a consistent schedule always exists (no maximum duration for off/standby/heat).
- Multi-phase algorithm (Fig. 4): preprocessing restricts feasible decompositions (temporal — heat-only between close acquisitions; thermal — off-mode decompositions only between far apart acquisitions); Phase 1 heuristic schedule (lowest total minimum duration, best-date dispatching rule, estAlone/lstAlone, smallest best dates inserted first, all locks 0); Phase 2 temporal repair (chronological acquisitions, critical path, randomly select a critical arc between intervals of distinct instruments, move itv just after itv′, accepted iff it strictly reduces delay, then set lock_a = 1); Phase 3 resource optimization (chronological, decompositions that add no switch-off first, lowest thermal first, insertion heuristic); Phase 4 resource repair (add off intervals on violated orbits, longest global transitions first); Phase 5 backtrack-free solution extraction (latest consistent value for intervals on the right of the interval to enlarge, earliest otherwise, propagate in the temporal network — STN decomposability), stop if thermal constraints hold, else return to Phase 4, else inconsistency.
