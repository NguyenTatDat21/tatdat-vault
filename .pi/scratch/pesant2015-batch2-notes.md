## idx 23 — Generalized Totalizer Encoding for Pseudo-Boolean Constraints (lines 6595–6806, full)
- Problem: encode pseudo-Boolean constraints (PBC, "0-1 Integer Linear Constraints") into SAT so off-the-shelf SAT solvers can solve them; SAT runtime is sensitive to the encoding used (L6595, L6603). Decision problem only (PBS), not PBO optimisation (L6621).
- Model/formulation: normal form `sum w_i l_i <= k` — Eqn. (1) (L6618); literals positive/negative, weights in N+ (L6609, L6621). GTE = arc-consistency-preserving extension of Totalizer encoding, visualised as a binary tree; each node `(node name : node vars : node sum)`, node variable `a_w` witnesses weighted sum w of its subtree (L6603, L6625, L6629). Parent propagation clauses — Eqn. (2) (L6634), explained (L6637). Weighted sums above k are collapsed to `k + 1` — generalisation of k-simplification, `w3 = min(w1 + w2, k + 1)` (L6639). Root clause `neg O_{k+1}` — Eqn. (3) (L6644). Number of node variables at node A = `|unique({Weight(S) | S ⊆ A_Iw ∧ S ≠ ∅})|` — Eqn. (4) (L6650). Auxiliary variable count depends on #distinct weighted-sum combinations, not on weight magnitudes (L6653). GAC of Totalizer carries over to GTE (L6661).
- Complexity claims (as stated): exponential worst case when weights are `2^0 … 2^(n-1)` (L6655); polynomial size when largest weight is a polynomial P(n), distinct combinations bounded by `n P(n)` (L6657); best case (all weights equal) `O(n log2 n)` auxiliary variables and `O(n^2)` clauses, and `O(n k)` variables and clauses with k-simplification (L6659). Related work: adder-circuit encoding `O(n log2 k)` auxiliary clauses, not arc-consistent; sorting-network encoding `O(N log2^2 N)` clauses with `N = sum ceil(log2 w_i)`, not arc-consistent for PBCs, GAC for cardinality (L6665); Watchdog first polynomial GAC encoding, `O(n^3 log2 n log2 wmax)` clauses; Binary Merger reduces to `O(n^2 log2^2 n log2 wmax)` (L6667); BDD encodings exponential worst case, GAC, weight-magnitude-independent (L6669); SWC sequential weighted counter can be exponential (L6671).

## idx 26 — On Tree-Preserving Constraints (lines 7667–8022, full)

- Problem: the subgraph isomorphism problem — finding a pattern graph inside a target graph (L8871); applications in bioinformatics [3], chemistry [31], computer vision [12,37], law enforcement [7], model checking [33] and pattern recognition [9] (L8875). The CP model has one variable per pattern-graph vertex with the target-graph vertices as domains, rules about preserving adjacency, and an all-different constraint across all the variables (L8875). Non-induced subgraph isomorphism is an injective mapping i: P ↦ T preserving adjacency, so a loop must map to a loop; the induced version additionally requires non-adjacency to be preserved; directed and labelled variants exist; all these variants are NP-complete, and the paper discusses only the non-induced version (L8901).
- Model/formulation: graphs finite, undirected, no multiple edges, loops allowed; V(G), N(G,v), degree, neighbourhood degree sequence S(G,v) from largest to smallest, isolated vertex, G[V] (L8899); R ⪯ S when a subsequence of S of R's length dominates R elementwise (L8903); path, cycle, distance, G^d = edges between vertices at distance at most d, G^[c,l] = edges between v,w (not necessarily distinct) precisely if there are at least c paths of length exactly l (L8905). Proposition 1 (L8907): i is also (1) a subgraph isomorphism i^d: P^d ↦ T^d for any d ≥ 1 (L8909) and (2) i^[c,l]: P^[c,l] ↦ T^[c,l] for any c,l ≥ 1 (L8911); SND uses the contrapositive of the first fact for dynamic distance-based filtering, this paper uses the second fact at the top of search to generate implied constraints (L8913). Algorithm 1 (caption L8924, body L8925–L8933): if |V(P)| > |V(T)| return false, discard isolated pattern vertices, createSupplementalGraphList, init, return false if countingAllDifferent(D) ≠ Success, return search(L,D) = Success. Algorithm 2 (caption L8936, pairs at L8939–L8940): (P,T), (P^[1,2],T^[1,2]), (P^[2,2],T^[2,2]), (P^[3,2],T^[3,2]), (P^[1,3],T^[1,3]), (P^[2,3],T^[2,3]), (P^[3,3],T^[3,3]). Algorithm 3 init (caption L8950): variable per pattern vertex with target vertices as domain, degree filter, neighbourhood degree sequence filter v ↦ w only if S(P,v) ⪯ S(T,w), domains restricted to the pairwise intersections, R ← ⋃_v D_v, repeat until R unchanged, supplemental graphs not recomputed for performance (L8945, L8947). Algorithm 4 recursive search (caption L8962, body from L8965): succeed when D = ∅, pick the min-size domain tiebreaking on static degree in P, values ordered by static degree in T, clone D, call assign, on Fail F′ add to F, on success recurse on D′ − D_v; if the subsearch failed and the assignment removed no value from any domain in the nogood, ignore the assignment and backtrack — clone-comparing CDB-style backjumping with lazily built conflict sets, a reduced conflict explanation from the all-different propagator improving backjumping (L8983, L8985, L8891). Algorithm 5 assign (caption L8988, which the source prints as 'Variable assignment for Algorithm 5'): D_v ← {v′}, delete v′ from every other domain, for each pair D_w ← D_w ∩ N(T,v′) for w adjacent to v, wipeout → Fail {w}, then return countingAllDifferent(D) (L9000). Failed Hall set = n variables whose domains contain strictly less than n values; Hall set = n variables whose domains contain only n values, so those values can be deleted from all other domains; the canonical method is Régin's matching-based propagator [30] (L9002); matching is expensive, does relatively little for large domains, and not maintaining arc consistency means the intermediate inference is a heuristic towards matching (L9004). Algorithm 6 counting-based all-different (caption L9009, body L9012–L9019): (F,H,A,n) ← (∅,∅,∅,0); foreach domain D_v from smallest to largest cardinality; F ← F + v; D_v ← D_v \ H; (A,n) ← (A∪D_v, n+1); return Fail F if D_v = ∅ or |A| < n; if |A| = n then (H,A,n) ← (H∪A, ∅, 0); return Success (L9012–L9019). Bit- and thread-parallelism (L9028–L9046): graphs as arrays of bit vectors, domains as bit vectors, neighbourhood intersection by bitwise-and, unions in Algorithms 4 and 6 by bitwise-or, cardinality checks in Algorithm 6 by population count (single instruction on modern CPUs); parallelise the outer loops of neighbourhood degree sequences, domain initialisation and supplemental graph construction, adding edges via an atomic 'or'; parallel subtrees are speculative because the foreach may exit early, knowledge is never passed to the left on a backjump condition (safety and reproducibility, so no linear speedup is expected on unsatisfiable instances), success is returned immediately by any thread (parallel search may return a different solution, and superlinear speedups are possible on satisfiable instances), and work stealing prioritises subproblems highest up then furthest left in the search tree.
- Exact results: LAD or SND sometimes make less than one recursive call per second with larger target graphs; on the same hardware the paper's algorithm makes '$1 0 ^ { 4 }$ to $1 0 ^ { 6 }$' recursive calls per core per second (printed in LaTeX form, L8877). Supplemental-graph rationale (L8943): distances of greater than 3 rarely give additional filtering power; constructing G^[c,4] is computationally very expensive, NP-hard for unbounded l; checking c > 3 rarely beneficial; the choice is somewhat arbitrary and expensive for trivial instances, so instance-by-instance configuration is possible [23]. Counting all-different cost (L9022): sorting step O(v log v) where v = number of remaining variables, loop O(vd) where d = cost of a bitset operation over a target domain. - Conclusions/claims: weaker propagation and backjumping have fallen out of fashion in general, but here this approach usually pays off, and over a large collection of standard instances the solver is the single best (L8895). Overall ours is the single best solver, VF2 is stronger on trivial instances because time must be spent constructing supplemental graphs, so VF2 (or this algorithm without supplemental graphs) may be worth using as a presolver when short runtimes for trivial queries matter, as in graph database systems [16] which could cache supplemental graphs, and there is scope for algorithm portfolios and instance-specific configuration, e.g. omitting or using different supplemental graphs (L9074, L9082). Fig. 3: a reasonable general improvement from parallelism except at very low sequential runtimes, strongly superlinear speedups for some satisfiable instances, which are exceptionally hard problems [35]; the work stealing strategy avoided strong commitment to early value-ordering heuristic choices, providing an alternative to more complicated sequential search strategies (L9086). Fig. 4: backjumping usually at least pays for itself, explicit conflict sets cost a small average slowdown, and backjumping improves by several orders of magnitude on a few instances, most visible on the LV benchmarks, mirroring Chen and Van Beek [5] that CBJ can speed up backtracking by several orders of magnitude on hard, structured problems, and that real-world graphs often have unexpected structural properties not present in random instances [22,34], so backjumping is considered worthwhile (L9094, L9096, L9116). Counting all-different: little to no benefit from Régin's algorithm for most graph families even with no performance cost, a gain only in a small portion of the LV graphs, one penalty from dynamic variable ordering (L9120); counting is nearly always as good as matching, or neither propagator does much in this domain, and the large number of points below the diagonal confirms going beyond simple value deletion is worthwhile (L9122). Conclusion: replacing strong inference with cheaper surrogates could pay off, backjumping can be implemented cheaply enough to be beneficial, parallelism gave a substantial benefit even for relatively low runtimes because parallelism is exploited for preprocessing as well as search, parallel backjumping has had only limited attention [8,10,17], and a simple approach worked reasonably well here, in contrast to stronger clause-learning systems where parallel successes appear rare (L9126). Extensions: domain- or instance-specific supplemental graphs not deeply investigated, directed graphs and induced isomorphisms not discussed (supplemental graphs can be taken further; composing transformations for induced isomorphisms would allow reasoning about 'paths of non-edges', which may be very helpful), and symmetries and dominance relations present in many graph instances have not yet been exploited (L9128).
