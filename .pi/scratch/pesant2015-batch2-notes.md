## idx 23 — Generalized Totalizer Encoding for Pseudo-Boolean Constraints (lines 6595–6806, full)
- Problem: encode pseudo-Boolean constraints (PBC, "0-1 Integer Linear Constraints") into SAT so off-the-shelf SAT solvers can solve them; SAT runtime is sensitive to the encoding used (L6595, L6603). Decision problem only (PBS), not PBO optimisation (L6621).
- Model/formulation: normal form `sum w_i l_i <= k` — Eqn. (1) (L6618); literals positive/negative, weights in N+ (L6609, L6621). GTE = arc-consistency-preserving extension of Totalizer encoding, visualised as a binary tree; each node `(node name : node vars : node sum)`, node variable `a_w` witnesses weighted sum w of its subtree (L6603, L6625, L6629). Parent propagation clauses — Eqn. (2) (L6634), explained (L6637). Weighted sums above k are collapsed to `k + 1` — generalisation of k-simplification, `w3 = min(w1 + w2, k + 1)` (L6639). Root clause `neg O_{k+1}` — Eqn. (3) (L6644). Number of node variables at node A = `|unique({Weight(S) | S ⊆ A_Iw ∧ S ≠ ∅})|` — Eqn. (4) (L6650). Auxiliary variable count depends on #distinct weighted-sum combinations, not on weight magnitudes (L6653). GAC of Totalizer carries over to GTE (L6661).
- Complexity claims (as stated): exponential worst case when weights are `2^0 … 2^(n-1)` (L6655); polynomial size when largest weight is a polynomial P(n), distinct combinations bounded by `n P(n)` (L6657); best case (all weights equal) `O(n log2 n)` auxiliary variables and `O(n^2)` clauses, and `O(n k)` variables and clauses with k-simplification (L6659). Related work: adder-circuit encoding `O(n log2 k)` auxiliary clauses, not arc-consistent; sorting-network encoding `O(N log2^2 N)` clauses with `N = sum ceil(log2 w_i)`, not arc-consistent for PBCs, GAC for cardinality (L6665); Watchdog first polynomial GAC encoding, `O(n^3 log2 n log2 wmax)` clauses; Binary Merger reduces to `O(n^2 log2^2 n log2 wmax)` (L6667); BDD encodings exponential worst case, GAC, weight-magnitude-independent (L6669); SWC sequential weighted counter can be exponential (L6671).
- Exact results: hardware "two AMD 6276 processors (2.3 GHz) running Fedora 18", timeout 1,800 seconds, memory limit 16 GB; PBLib version 1.2; Minisat 2.2.0 backend (L6675). Benchmarks: 355 instances in DEC-SMALLINT-LIN category of PB evaluation of 2012, 214 selected with at least 1 PBC; pedigree benchmarks from computational biology, MaxSAT Evaluation of 2014; 200 generated instances, 172 with at least 1 PBC; satisfiable uses `k_opt`, unsatisfiable `k_opt − 1` (L6677). - Conclusions/claims: GTE is exponential in the worst case but "very competitive" against other PBC encodings; when the number of different weights is small it "clearly outperforms all other encodings"; extendable to incremental settings (L6741). gte competitive with bdd, bin-merger, watchdog on PB'12; only gte and bdd tackle pedigree benchmarks (L6729). Runtime on pedigree "establishes gte as the clear winner with bdd performing a close second" (L6735); gte clause count is large relative to other encodings, bdd generates smaller formulas in practice (L6733); swc variable explosion grows with k while bdd and gte reuse variables (L6731); sorter, adder, swc perform worse (L6693, L6727).

## idx 24 — Smaller Selection Networks for Cardinality Constraints Encoding (lines 6807–7259, full)
- Problem: build selection comparator networks that are smaller than pairwise selection networks, for encoding cardinality constraints `x1 + ... + xn ~ k` into CNF for SAT solvers, and prove that standard CNF encodings of selection networks preserve arc-consistency (L6813, L6819).
- Model/formulation: odd-even sorting network (Batcher) and pairwise sorting network (Parberry 1992) have "exactly the same size and depth" (L6817). Cardinality relation `~` from `{ = , < , <= , > , >= }` (L6819). Definitions: input sequence, comparator `c_ij`, comparator network size `|f^n|`, v-shaped/bitonic, sorting network, top-k sorted sequence, selection network `f^n_k` (L6837, L6849, L6855, L6857, L6859, L6863, L6865). n and k assumed powers of 2 (L6867). Arc-consistency definition: when `k − 1` variables become true, unit propagation sets all others false (L6873). Full comparator encoding `fcomp` = 6 clauses (L6883); half encoding `hcomp` = 3 clauses `(a⇒c) ∧ (b⇒c) ∧ (a∧b⇒d)` (L6885, L6888); k-th output forced 0 by clause `¬y_k` (L6875). Splitter `split^n` size `n/2` (Observation 1, L6901); bitonic splitter `bit_split^n` size `n/2` (Observation 3, L6926); pairwise merger `|pw_merge^n_k| = k log k − k + 1` (L6922); `|bit_merge^n| = n log n / 2`, base case n = 2 single comparator (L6928). Networks 1–4 given as pseudocode blocks (L6910–6918, L6937–6946, L6967–6972, L7017–7026). Theorems 1–6, Lemmas 1–14, Corollary 1, Remarks; propagation tree T rooted at `y_k` (L7214, L7218).

(2): `|bit_sel^n_k| = (n/k)|oe_sort^k| + (n/k − 1)(|bit_split^{2k}| + |bit_merge^k|) = 1/4 n log^2 k + 1/4 n log k + 2n − 1/2 k log k − k − n/k` (L6955); termination after `log(n/k)` iterations (L6950). - Conclusions/claims: new family of selection networks requiring fewer comparators to merge subsequences, size difference grows with k, equal to `n (log n − 4)/2 + log n + 2` at `k = n/2` (L7230); any selection network encoded in the standard way preserves arc-consistency w.r.t. its cardinality constraint, important because SAT solvers use unit propagation (L7230); encodings support incremental strengthening — only one extra clause `¬y_k` per decreasing k, since a k-selection network is also a k'-selection network for `k' < k` (L7232); savings expected in SAT performance "but the statement needs an experimental evaluation", evaluation started, results to be presented in the near future (L7234); the relative size saving is largest when k > n/2, upper bound approximates well for small n (L7158).
